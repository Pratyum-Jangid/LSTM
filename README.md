## 📌 Overview

The **DRISHTI** is a deep-tech computer-vision system designed to bridge the gap between **drone detection** and **actionable intelligence**.

The proliferation of **commercial, autonomous, and DIY drones has created a growing challenge for military forces and critical security infrastructure**. Unauthorized or hostile UAVs can be used for reconnaissance, surveillance, intelligence gathering, or intrusion around military bases, strategic installations, restricted airspace, and other high-value assets.

A conventional object detector can identify a drone in the current frame, but **detection alone is reactive**.

For military surveillance operators, the critical question is not only:

> **“Is there a drone?”**

but:

> **“Where is it heading, what is its movement pattern, and where is it likely to be next?”**

A conventional detection system does not inherently understand:

* where the drone is heading,
* how its trajectory is changing over time,
* whether it is moving toward a restricted or protected zone,
* where it is likely to be in the next few moments,
* or whether its observed movement warrants further attention.

This creates a gap between **detection and actionable situational awareness**.

The current working foundation combines:

**Video → YOLO11 → ByteTrack → Trajectory Extraction → LSTM → Future Trajectory Prediction**

The broader architecture is designed to evolve toward **threat assessment, retrieval-augmented intelligence, local LLM reporting, and an operator-focused command dashboard.**

---

**DRISHTI** addresses this gap by extending drone surveillance from **frame-level detection to persistent tracking and trajectory prediction**, providing a foundation for earlier awareness of potentially anomalous or unauthorized drone movement around military and other high-security environments.

### The core limitations

| Problem                        | Why it matters                                              |
| ------------------------------ | ----------------------------------------------------------- |
| **Single-frame detection**     | Knowing that a drone exists is not enough                   |
| **Loss of object identity**    | Operators need to follow the same drone over time           |
| **No temporal reasoning**      | Frame-by-frame detection does not model movement            |
| **No future trajectory**       | Operators receive information after movement occurs         |
| **Human monitoring burden**    | Long surveillance streams create cognitive overload         |
| **Limited intelligence layer** | Detection alone does not translate into operational context |

Research and existing benchmarks predominantly focus on **detection and tracking**, while combining persistent tracking, trajectory prediction, behavioral assessment, contextual retrieval, and natural-language intelligence remains a more challenging system-level problem.

# 🧠 Deep-Tech Core

## 01 — Drone Detection

### YOLO11

The detection layer uses a custom-trained **YOLO11** model to identify drones in aerial/surveillance footage.

For every detected object, the system can obtain:

* Bounding box
* Class
* Confidence score
* Frame location

```text
Frame
   │
   ▼
YOLO11
   │
   ├── Drone #1
   │     ├── Bounding Box
   │     └── Confidence
   │
   └── Drone #2
         ├── Bounding Box
         └── Confidence
```

The detection stage forms the perception layer of the platform.

---

# 02 — Persistent Multi-Object Tracking

## ByteTrack

Detection alone treats every frame independently.

ByteTrack adds **temporal identity**.

Instead of:

```text
Frame 1 → Drone
Frame 2 → Drone
Frame 3 → Drone
```

the system maintains:

```text
Frame 1 ─┐
Frame 2 ─┼──→ Drone #3
Frame 3 ─┤
Frame 4 ─┘
```

This enables:

* Persistent IDs
* Multi-drone tracking
* Track history
* Trajectory generation
* Improved continuity during temporary occlusions

The completed detection and tracking module has been demonstrated on uploaded video, producing annotated output with tracking trails and persistent IDs.

---

# 03 — Trajectory Extraction

Once a persistent track is established, the platform converts the object's movement into a temporal trajectory.

For each tracked object, the pipeline can derive features such as:

* Center coordinates
* Bounding-box dimensions
* Position changes
* Velocity
* Speed
* Heading
* Acceleration

Conceptually:

```text
Track ID: 3

t1 → (x₁, y₁)
t2 → (x₂, y₂)
t3 → (x₃, y₃)
t4 → (x₄, y₄)
...
```

These temporal sequences provide the foundation for prediction.

---

# 04 — Predictive Intelligence

## LSTM-Based Trajectory Prediction

The next layer uses an **LSTM temporal model** to learn movement patterns from historical trajectories.

Instead of only observing:

```text
Where is Drone #3 now?
```

the system attempts to estimate:

```text
Where is Drone #3 going?
```

### Prediction pipeline

```text
Historical Track
       │
       ▼
Temporal Sequence
       │
       ▼
Motion Features
       │
       ▼
      LSTM
       │
       ▼
Future Positions
```

The current prototype supports short-horizon trajectory prediction, with the demonstration focused on the **next five predicted positions**.

Example:

```text
TRACK ID: 3

Observed trajectory
        ↓
       LSTM
        ↓
Predicted trajectory

t+1 → (x₁, y₁)
t+2 → (x₂, y₂)
t+3 → (x₃, y₃)
t+4 → (x₄, y₄)
t+5 → (x₅, y₅)
```

This transforms the platform from a conventional detector into a **trajectory-aware predictive system**.

# 🏗️ Seven-Layer Intelligence Architecture

The long-term system is designed as a modular seven-layer architecture.

### Layer 1 — Drone Detection

**YOLO11**

Detect and localize drones in aerial video.

### Layer 2 — Multi-Object Tracking

**ByteTrack**

Maintain persistent identities across frames.

### Layer 3 — Trajectory Prediction

**LSTM / Transformer**

Forecast future movement from temporal trajectories.

### Layer 4 — Threat Assessment

**Rule Engine + ML**

Combine kinematic, spatial, and behavioral features to estimate risk.

### Layer 5 — RAG Intelligence

**FAISS / Qdrant + Sentence Transformers**

Retrieve relevant drone specifications, SOPs, regulations, and domain knowledge.

### Layer 6 — Intelligence Reporting

**Local LLM**

Convert structured system outputs into grounded natural-language intelligence summaries.

### Layer 7 — Command Dashboard

**React / Next.js + Map-based visualization**

Provide an operator-facing interface for monitoring, alerts, trajectories, and reports.

> **Layers 1–3 form the current core research prototype. Layers 4–7 represent the planned intelligence expansion.**

# 📈 Performance & Research Considerations

Drone intelligence presents several difficult computer-vision challenges.

### Small Objects

Drones may occupy extremely small regions of the frame, particularly in distant aerial footage.

### Motion Blur

High-speed drone movement can create blurred frames and reduce detection confidence.

### Low Visibility

Night-time, infrared, haze, and low-contrast environments introduce additional detection difficulty.

### Tracking Fragility

Crossovers and prolonged occlusion can result in identity switches or lost tracks.

### Data Scarcity

There is limited public data combining:

```text
Drone Trajectory
      +
Threat Label
      +
Operational Context
      +
SOP / Domain Knowledge
```

This creates a major research challenge for future threat-assessment and intelligence layers.

## Requirements

Recommended environment:

* Python 3.11
* Git

## 🌐 Online Installation

Clone the repository:

```bash
git clone https://github.com/hitakshijoshi20072911/DRSIHTI.git
cd DRSIHTI
```

Create a virtual environment:

### Windows

```bash
python -m venv .venv
.venv\Scripts\activate
```

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Upgrade pip:

```bash
python -m pip install --upgrade pip
```

Install dependencies:

```bash
pip install -r requirements.txt
```

---

# 🔒 Offline Installation

The project can also be prepared for environments without internet access.

If all required Python wheels are stored inside:

```text
wheels/
```

create and activate the environment:

```bash
python -m venv .venv
```

### Windows

```bash
.venv\Scripts\activate
```

Install exclusively from the local wheel repository:

```bash
python -m pip install --no-index --find-links=./wheels -r requirements.txt
```

This prevents pip from accessing PyPI.

### Verify the environment

```bash
python --version
```
